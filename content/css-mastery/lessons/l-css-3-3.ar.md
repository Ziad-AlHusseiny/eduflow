اختيرت ألوان المسارات الأربعة في Waypoint واحدًا تلو الآخر في أداة تصميم، كأكواد hex. بدا وردي Design صاخبًا، وأخضر Accessibility باهتًا، ونجح النص الأبيض في الشارات في اختبار التباين على مسارين وفشل على الآخرَين. وحين احتاج الفريق إلى درجة فاتحة لخلفية شارة كل مسار، ولّد أحدهم ثمانية أكواد hex أخرى بالعين. ثم جاءت حالات المرور. عشرون لونًا، بلا نظام، ولا أحد يستطيع أن يقول لماذا `#0891b2` هو اللون الصحيح.

ألوان CSS الحديثة تتيح لك تعريف لون أساسي واحد لكل مسار، واشتقاق كل ما عداه بقواعد.

## لماذا oklch()

hex و`rgb()` و`hsl()` كلها تصف الألوان في فضاء sRGB، المنظّم حول طريقة إطلاق الشاشات للضوء، لا طريقة رؤية العين له. و«الإضاءة» في HSL أسوأ المذنبين: `hsl(60 100% 50%)` (الأصفر) و`hsl(240 100% 50%)` (الأزرق) يدّعيان الإضاءة نفسها، لكن الأصفر مبهر والأزرق داكن. وأيّ لوحة ألوان تُبنى بتدوير درجة اللون في HSL تنتهي بتباين متفاوت بشدّة.

`oklch()` مبنية على نموذج OKLab، المصمّم لتتبع الأرقامُ الإدراكَ:

- **L**، الإضاءة، من 0 (الأسود) إلى 1 أو 100% (الأبيض)، والـ L المتساوية تبدو بالإضاءة نفسها عبر درجات اللون.
- **C**، التشبّع اللوني (chroma)، من 0 (الرمادي) إلى نحو 0.37 لأكثر الألوان حيوية التي تستطيع الشاشات عرضها.
- **H**، زاوية درجة اللون بالدرجات: حول 30 أحمر، و140 أخضر، و250 أزرق، و350 وردي.

```css title=tokens.css
:root {
  --track-design: oklch(62% 0.19 350);
  --track-perf:   oklch(62% 0.19 220);
  --track-a11y:   oklch(62% 0.19 150);
  --track-platform: oklch(62% 0.19 280);
}
```

إضاءة واحدة، وتشبّع واحد، وأربع درجات لون. أصبحت المسارات تحمل وزنًا بصريًا متساويًا، وإن نجح النص الأبيض في اختبار التباين على أحدها فسيكون على مسافة قصيرة جدًا من النجاح على الأربعة. ما زلت تتحقّق من التباين (نماذج الإدراك ليست معادلات تباين)، لكنك تبدأ من نقطة قريبة بدل التخمين.

:::note نطاق لوني واسع مجانًا
تستطيع OKLCH وصف ألوان خارج sRGB، مثل الأخضر الحيوي الذي تستطيع شاشة P3 عرضه. وإن لم تستطع الشاشة عرض لون ما، ينقله المتصفّح إلى أقرب لون تستطيعه. ولهذا قد يبدو تشبّع عالٍ مثل 0.25 مختلفًا قليلًا بين هاتف جديد وشاشة قديمة. و`oklch()` ضمن Baseline منذ 2023 ومتاحة على نطاق واسع منذ أواخر 2025.
:::

## الدرجات الفاتحة والداكنة بـ color-mix()

تمزج `color-mix()` لونين في فضاء ألوان تختاره:

```css
.badge {
  background: color-mix(in oklch, var(--track) 15%, white);
  color: color-mix(in oklch, var(--track) 70%, black);
}
.session-card.is-cancelled {
  background: color-mix(in oklch, var(--track), transparent 85%);
}
```

النسبة المئوية تخصّ اللون الذي تليه؛ واللون الآخر يأخذ الباقي. لذا فإن `var(--track) 15%, white` أبيض في معظمه مع لمحة من لون المسار: خلفية شارة. والمزج مع `transparent` يُنتج نسخة شبه شفافة، دون الحاجة إلى token منفصل للشفافية.

فضاء الألوان يغيّر النتيجة. مزج الأزرق والأصفر `in srgb` يمرّ برمادي موحل؛ أما `in oklch` فتنتقل درجة اللون حول العجلة وتبقى حيوية. ولدرجات الواجهة الفاتحة تعطي `oklch` أو `oklab` أكثر الخطوات انتظامًا. و`color-mix()` ضمن Baseline 2023.

:::mistake التعتيم بالمزج مع الأسود لحالات المرور
`color-mix(in srgb, var(--track), black 20%)` تبدو جيدة على الوردي، لكن فضاء sRGB ليس منتظمًا إدراكيًا: النسبة نفسها، 20%، تُغمق بعض درجات اللون أكثر بكثير من غيرها وتُخمد تشبّعها، فلا تعود حالات المرور الأربع متطابقة. حين تريد «اللون نفسه، أغمق قليلًا» بمقدار يمكن توقّعه، غيّر الإضاءة وحدها، وهذا بالضبط ما وُجدت له الألوان النسبية.
:::

## الألوان النسبية: عدّل قناة واحدة

صيغة الألوان النسبية تفكّ اللون الأساسي إلى قنواته، وتتيح لك تغيير أيٍّ منها، ثم تعيد تركيبه:

```css
.session-card {
  --track: var(--track-design);
  border-inline-start: 6px solid var(--track);

  &:hover,
  &.is-active {
    border-color: oklch(from var(--track) calc(l - 0.15) c h);
  }

  &.is-past {
    border-color: oklch(from var(--track) l 0.03 h);   /* nearly grey, same hue */
  }

  & .badge-soft {
    background: oklch(from var(--track) l c h / 20%);  /* same color, 20% alpha */
  }
}
```

بعد `from var(--track)` تحمل الكلمات المفتاحية `l` و`c` و`h` قنوات اللون الأساسي كأرقام، وتستطيع استخدامها في `calc()`. لاحظ أن `l` هنا رقم من 0 إلى 1، لذا فطرح 0.15 يُغمق اللون 15 نقطة. وكل حالة مشتقّة تتبع الآن اللون الأساسي تلقائيًا: أضف مسارًا خامسًا، وستوجد أشكال المرور والماضي والدرجة الناعمة الخاصة به لحظة تعريف لونه الأساسي.

الألوان النسبية ضمن Baseline 2024، في Chrome وEdge وFirefox وSafari. وإن كان عليك دعم متصفّحات أقدم، فلا تعتمد على تصريح احتياطي ثابت تكتبه قبلها: هذه القيم تحتوي على `var()`، فيقبلها المتصفّح القديم وقت التحليل، ثم يقع في فخّ «غير صالح في وقت حساب القيمة» الذي رأيته في درس [الـ Custom Properties و@property](lesson:l-css-1-4)، فيضيع البديل أيضًا. بدلًا من ذلك غلّف الحالات المشتقّة بـ `@supports (color: oklch(from red l c h)) { … }`، فتحتفظ المتصفّحات القديمة بالقاعدة الأساسية.

:::tip اقرأ الألوان في DevTools وأنت تعمل
يعرض Chrome وFirefox عيّنة لونية بجوار كل لون، والنقر عليها يفتح منتقي ألوان يستطيع عرض OKLCH والتحويل إليها. وحين يبدو لون مشتقّ خاطئًا، تخبرك القيمة المحسوبة بالضبط بما انتهت إليه `l` و`c` و`h`.
:::

## دورك الآن

لبطاقة التمرين قيم hex مكتوبة يدويًا لدرجة الشارة الفاتحة وللحدّ في الحالة النشطة. استبدلها بدرجة فاتحة بـ `color-mix()` وحالة نشطة بلون نسبي، وأضف مسار Performance يطابق مسار Design في الإضاءة والتشبّع. تقرأ الفحوصات قنوات OKLCH المحسوبة. وبعدها ستنقل لوحة الألوان هذه إلى الوضع الداكن باستخدام `color-scheme` و`light-dark()`.
