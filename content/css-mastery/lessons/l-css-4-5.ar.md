بدا جدول Waypoint مكتملًا، ثم فتحه الفريق على هاتف Android عمره ثلاث سنوات عبر شبكة Wi-Fi المزدحمة في قاعة المؤتمر. تقطّع إشعار الحفظ، وبدا التمرير الأول لزجًا، ودفعت صور المتحدّثين النص إلى الأسفل وهي تُحمَّل. لم يكن شيء معطوبًا؛ كانت الصفحة ببساطة تؤدّي عملًا أكثر مما تحتاج.

أداء CSS يعود إلى سؤال واحد: *كم من مراحل خط الرسم يجبر هذا التغيير المتصفّح على تشغيلها؟*

## خط الرسم في المتصفّح

بعد أن تغيّر الـ CSS شيئًا ما، يشغّل المتصفّح حتى أربع مراحل لتحديث الشاشة:

1. **الأنماط (Style)**: تحديد القواعد المنطبقة وحساب قيم كل عنصر.
2. **التخطيط (Layout)**: حساب حجم كل صندوق وموضعه.
3. **الرسم (Paint)**: ملء البكسلات: النصوص والألوان والحدود والظلال والصور.
4. **التركيب (Composite)**: تجميع الطبقات المرسومة على الـ GPU، مع تطبيق الـ transforms والشفافية.

السرّ أن كل تغيير لا يحتاج إلا إلى البدء من مرحلة معيّنة. غيّر `width` فيجب أن يعمل التخطيط، ثم الرسم، ثم التركيب. وغيّر `background-color` فيمكن تخطّي التخطيط. وغيّر `transform` أو `opacity` على عنصر له طبقة خاصة به، فيستطيع المتصفّح تخطّي التخطيط *والرسم* معًا، وتحريك بكسلات موجودة أصلًا على الـ GPU.

## حرّك الخصائص الرخيصة

كان إشعار الحفظ يتحرّك هكذا:

```css
@keyframes toast-in {
  from { left: -320px; }
  to   { left: 16px; }
}
```

`left` خاصية أبعاد: كل إطار يعيد تشغيل التخطيط للإشعار (ويفحص هل تحرّك أيّ شيء آخر)، ثم يعيد الرسم. والإصلاح يُبقي موضع الإشعار ثابتًا ويحرّك صورته بدلًا من ذلك:

```css
.toast {
  position: fixed;
  left: 16px;
  bottom: 16px;
  animation: toast-in 250ms ease-out;
}

@keyframes toast-in {
  from { translate: -336px 0; opacity: 0; }
  to   { translate: 0 0;      opacity: 1; }
}
```

النتيجة البصرية نفسها، بجزء صغير من العمل. ولهذا استخدمت كل حركة في هذه الدورة `translate` و`scale` و`opacity` وأخواتها. والمنطق نفسه ينطبق على الـ transitions: مرورٌ يغيّر `box-shadow` يعيد الرسم في كل إطار، وهذا مقبول لبطاقة واحدة وملحوظ لشبكة من خمسين بطاقة تتحرّك معًا. وإظهار ظلّ مرسوم مسبقًا على pseudo-element بتحريك `opacity` هو البديل الأرخص حين يهمّ الأمر.

:::mistake will-change في كل مكان
`will-change: transform` تطلب من المتصفّح أن يرفع العنصر إلى طبقة خاصة به مسبقًا. على العنصر الوحيد الذي يوشك أن يتحرّك، قد يتجنّب ذلك تعثّرًا في البداية. أما على كل بطاقة «احتياطًا»، فتنشئ عشرات الطبقات التي تكلّف كلٌّ منها ذاكرة من الـ GPU، وقد يجعل ذلك الصفحة أبطأ، خصوصًا على الهواتف. أضفها قبيل الحركة مباشرةً (أو عند `:hover` على العنصر الأب) ثم تخلَّ عنها بعدها؛ وفي الغالب لا تحتاج إليها أصلًا.
:::

## تخطَّ العمل الذي لا تراه

يرسم الجدول جلسات يومين، لكن المستخدم يرى ملء شاشة واحدة في كل مرة. `content-visibility: auto` تتيح للمتصفّح تخطّي التخطيط والرسم للأقسام الواقعة خارج الشاشة:

```css
.day {
  content-visibility: auto;
  contain-intrinsic-size: auto 1200px;
}
```

المحتوى المتخطّى ليس له حجم، لذا تعطي `contain-intrinsic-size` المتصفّح تقديرًا يستخدمه كعنصر نائب؛ ومع `auto` يتذكّر الحجم الحقيقي بعد أن يُرسم القسم مرة. ودونها تنهار الأقسام إلى الصفر ويقفز شريط التمرير أثناء التمرير. يبقى المحتوى في الـ DOM وفي شجرة إمكانية الوصول، ويظل البحث داخل الصفحة يعمل. و`content-visibility: auto` ضمن Baseline منذ سبتمبر 2025، حين أضاف Safari 26 القيمة `auto`؛ والمتصفّح الذي لا يدعمها يرسم كل الأقسام ببساطة، كما كان يفعل من قبل.

## لا تحرّك الأشياء بعد ظهورها

مقياس Cumulative Layout Shift، أحد مقاييس Core Web Vitals، يقيس قفز المحتوى أثناء تحميل الصفحة. وفي CSS يكون المذنب المعتاد وسائط بلا مساحة محجوزة. صورة متحدّث لها `width: 100%` بلا ارتفاع يكون ارتفاعها 0px حتى تصل الصورة، ثم تدفع كل شيء إلى الأسفل. احجز المساحة:

```css
.speaker img {
  width: 100%;
  height: auto;
  aspect-ratio: 1;
  object-fit: cover;
}
```

سمتا `width` و`height` على `<img>` تؤدّيان العمل نفسه، لأن المتصفّحات تستنتج منهما نسبة الأبعاد. وللخطوط من الويب، `font-display: swap` مع خط احتياطي بمقاييس مشابهة تمنع النص من إعادة الانسياب حين يُحمَّل الخط.

:::tip قِس أولًا
افتح لوحة Performance في DevTools، وسجّل تمريرًا أو تفاعلًا، وابحث عن الكتل البنفسجية الطويلة (الأنماط والتخطيط) والخضراء (الرسم). وخيار «Paint flashing» في لوحة Rendering يُبرز ما يُعاد رسمه. حسّن ما يُظهره التسجيل، لا ما تشكّ فيه.
:::

## أين أنت الآن

على مدى عشرين درسًا نقلت جدول Waypoint من ملف أنماط يصارعك إلى ملف تستطيع توقّعه: الـ layers و`:where()` تحسم التعارضات، والـ custom properties تكشف واجهات الـ components، وgrid والـ subgrid والـ container queries تتولّى التخطيط، و`oklch()` و`light-dark()` تتولّيان الألوان، والخصائص المنطقية تجعله يعمل بالعربية، والحركة لطيفة ورخيصة. والعادة التي تستحق أن تحتفظ بها هي عادة الدرس الأول: قبل أن تغيّر الـ CSS، توقّع ما سيفعله المتصفّح، ثم تحقّق.
