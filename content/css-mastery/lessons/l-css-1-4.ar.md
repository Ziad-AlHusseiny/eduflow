تأتي بطاقات الجلسات في Waypoint في أربعة مسارات (Design وPerformance وAccessibility وPlatform)، ولكل مسار لونه الخاص للحدّ الجانبي والشارة وحالة المرور فوق العنوان. النسخة الأولى كانت فيها قاعدة لكل مسار لكل عنصر: اثنتا عشرة قاعدة، وثالثة عشرة تُضاف كلما أضاف فريق التسويق مسارًا.

الـ custom properties (الخصائص المخصّصة، أو «متغيّرات CSS») تحوّل ذلك إلى قاعدة واحدة لكل مسار، وبطاقة تقرأ لونها من مقبض واحد.

## component بمقبض واحد

```css title=session-card.css
.session-card {
  border-inline-start: 6px solid var(--track-color, #64748b);
}
.session-card .badge {
  background: var(--track-color, #64748b);
  color: white;
}

.track-design { --track-color: #db2777; }
.track-perf   { --track-color: #0891b2; }
```

```html
<article class="session-card track-design">…</article>
```

أمران يجعلان هذا يعمل. الأول أن الـ custom properties **موروثة**: ضبط `--track-color` على البطاقة يجعلها مرئية للشارة داخلها. والثاني أن `var()` تُحسم **عند العنصر الذي يستخدمها**، في وقت حساب القيمة، فتستبدل كل بطاقة قيمتها الخاصة. والوسيط الثاني في `var()` هو القيمة البديلة، ولا تُستخدم إلا حين لا تكون الخاصية مضبوطة إطلاقًا.

المكان الذي تضبط فيه الـ custom property مهم. الـ design tokens العامة (ألوان العلامة التجارية وسلّم المسافات ومجموعات الخطوط) مكانها `:root`، ليرثها كل عنصر. أما tokens الـ component مثل `--track-color` فمكانها الـ component نفسه، لتبقى محلية وتستطيع بطاقة أن تختلف عن جارتها. وتغيير خاصية على `:root` من JavaScript يجبر المتصفّح على إعادة حساب الأنماط للشجرة كلها التي تستخدمها، لذا فإن ما يتغيّر كثيرًا، مثل موضع المؤشّر، اضبطه على أصغر عنصر يحتاج إليه.

فكّر في `--track-color` على أنها الواجهة العامة (API) للبطاقة. أيّ شخص يستطيع تغيير ثيم البطاقة من الخارج، في قالب CMS أو صفحة حملة لمرة واحدة، دون أن يعرف تفاصيلها الداخلية.

## حين يسوء الاستبدال

الـ custom properties غير المسجّلة مجرد سلاسل من الرموز. المتصفّح لا يعرف أن `--track-color` يُفترض أن تكون لونًا، لذا فإن `--track-color: 12px` تصريح صالح تمامًا. المشكلة تظهر لاحقًا، حين تُسقط `var()` القيمة `12px` في لون `border-inline-start`.

:::mistake توقّع أن ترجع CSS إلى التصريح السابق
مع خطأ إملائي عادي مثل `color: bleu`، يتخلّص المتصفّح من التصريح وقت التحليل ويبقى التصريح السابق منطبقًا. أما مع `var()` فيكون الـ cascade قد اختار التصريح الفائز قبل أن تُعرف القيمة. وحين يُنتج الاستبدال قيمة بلا معنى، تصبح الخاصية **غير صالحة في وقت حساب القيمة** وتأخذ قيمتها الموروثة أو الابتدائية، لا قيمة قاعدتك السابقة. والأمر أسوأ مع الخصائص المختصرة (shorthands): `border-inline-start: 6px solid 12px` غير صالحة بأكملها، فيُعاد ضبط السُّمك والنمط واللون جميعًا، والنمط الابتدائي هو `none`.
:::

وهكذا أطلقت Waypoint بطاقة بلا حدّ للمسار إطلاقًا وبشارة شفّافة: كتب الـ CMS القيمة `12px` في حقل اللون، ولم يعترض شيء.

## سجّل الخاصية بـ @property

تخبر `@property` المتصفّح بماهية الـ custom property:

```css
@property --track-color {
  syntax: "<color>";
  inherits: true;
  initial-value: #64748b;
}
```

الآن تتغيّر ثلاثة أشياء:

1. **فحص الصحة.** القيمة التي ليست `<color>` تجعل الخاصية تسقط إلى بديل آمن: تتصرّف كأنها غير مضبوطة، فتأخذ الخاصية الموروثة قيمة العنصر الأب، وتنتهي السلسلة عند `initial-value` إن لم يضبطها أحد. فتحصل البطاقة المعطوبة على حدّ رمادي مائل إلى الزرقة بدل ألّا يكون لها حدّ.
2. **القيم المحسوبة لها نوع.** `getComputedStyle(card).getPropertyValue('--track-color')` تُرجع `rgb(219, 39, 119)`، لا النص الخام الذي كتبته.
3. **الانتقال التدريجي.** المتصفّح يعرف كيف يمزج بين لونين، فيمكن للخاصية أن تدخل في transition.

يقبل الواصف `syntax` أنواعًا مثل `<color>` و`<length>` و`<length-percentage>` و`<number>` و`<percentage>` و`<angle>` و`<time>` و`<integer>`، إضافةً إلى `"*"` لأيّ شيء. و`initial-value` مطلوبة ما لم تكن الصيغة `"*"`، ويجب أن تكون مستقلة حسابيًا: `10px` مقبولة، أما `2em` فلا.

## تحريك ما كان يقفز

هذا تأثير مرور لا يمكن تحقيقه إلا بالتسجيل. الحافة العلوية للبطاقة تدرّج لوني زاويته custom property:

```css
@property --sheen-angle {
  syntax: "<angle>";
  inherits: false;
  initial-value: 90deg;
}

.session-card {
  background: linear-gradient(var(--sheen-angle), #f5f3ff, white 60%);
  transition: --sheen-angle 400ms ease;
}
.session-card:hover {
  --sheen-angle: 160deg;
}
```

دون `@property` لا يستطيع المتصفّح الانتقال تدريجيًا بين سلاسل رموز، فيقفز التدرّج من زاوية إلى أخرى. ومعها تتحرّك الزاوية بسلاسة. و`inherits: false` هي الصواب هنا: الزاوية تخصّ خلفية هذه البطاقة، ولا ينبغي أن تصل إلى العناصر الأبناء.

:::note الدعم
`@property` ضمن Baseline 2024 (متاحة حديثًا): يدعمها Chrome وEdge وSafari وFirefox، وهذا الأخير منذ الإصدار 128 في يوليو 2024. في المتصفّحات الأقدم تظل الخاصية تعمل كخاصية غير مسجّلة، لذا تعامل مع التسجيل على أنه تحسين تدريجي (progressive enhancement). ويمكنك أيضًا التسجيل من JavaScript بـ `CSS.registerProperty({ name, syntax, inherits, initialValue })`.
:::

:::tip سمِّ الـ tokens بدورها لا بقيمتها
`--track-color` تنجو من إعادة تصميم الهوية؛ أما `--pink-600` فلا. سمِّ الـ custom properties التي يقرؤها الـ component بحسب ما تفعله، واربطها بقيم لوحة الألوان الخام في مكان واحد.
:::

## دورك الآن

يعيد التمرين إنتاج خطأ الـ CMS: قيمة `--track-color` في إحدى البطاقات هي `12px`. سجّل الخاصية لتسقط القيم الخاطئة إلى الرمادي المائل إلى الزرقة (slate)، وتأكّد من أن ألوان المسارات الحقيقية ما زالت تظهر. ويواصل الدرس التالي العمل على هذه البطاقات بالـ nesting الأصلي و`:has()`، الذي يتيح للبطاقة أن تتفاعل مع ما بداخلها.
