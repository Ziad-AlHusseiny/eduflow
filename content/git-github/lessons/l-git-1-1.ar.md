لدى كل مطوّر مجلد ما فيه `index.html` و `index-old.html` و `index-final.html` و `index-final-REAL.html`. ينجح هذا الأسلوب حتى اليوم الذي تحتاج فيه إلى معرفة أي نسخة كانت فيها القائمة تعمل، أو ما الذي غيّرته بين الثلاثاء والخميس، أو كيف تجمع إصلاحك مع تعديلات صديقك من الصباح نفسه. النسخ المتفرّقة من الملفات لا تجيب عن أيّ من ذلك.

التحكم في الإصدارات (version control) هو الأداة التي تجيب عن هذه الأسئلة. فهو يحفظ سجلّ مشروعك كسلسلة من الحالات المحفوظة، لكل منها تاريخ ومؤلف وملاحظة تشرح السبب. تستطيع مقارنة أي حالتين، والعودة إلى حالة قديمة، وتجربة فكرة جانبية ثم رميها، ومشاركة السجلّ كاملًا مع الآخرين. و Git هو نظام التحكم في الإصدارات الذي تستخدمه الغالبية الساحقة من الفرق في 2026، و GitHub هو المكان الذي تحتفظ فيه معظم هذه الفرق بنسختها المشتركة.

## لقطات، لا تعديلات

فكرة Git الأساسية صغيرة. حين تنشئ commit (لقطة محفوظة)، يسجّل Git **لقطة** (snapshot): المحتوى الكامل لكل ملف يتتبّعه في تلك اللحظة. الملفات التي لم تتغيّر لا تُخزَّن مرتين، بل يعيد Git استخدام ما لديه أصلًا. ويخزّن كل commit أيضًا مؤشّرًا إلى الـ commit الذي سبقه، أي **الأب** (parent). اتبع هذه المؤشّرات إلى الخلف وستحصل على سجلّ المشروع.

لاحظ أن الأسهم تشير إلى الخلف. الـ commit يعرف أباه، ولا يعرف أبناءه أبدًا، لأن الأبناء لم يكونوا موجودين حين أُنشئ. هذه التفصيلة الواحدة تفسّر الكثير من سلوك Git لاحقًا، ومنه سبب عجزك عن «تعديل» commit قديم، وكل ما تستطيعه هو استبداله بآخر جديد.

## Git مقابل GitHub

يستخدم الناس الاسمين كأنهما شيء واحد، وهما ليسا كذلك.

- **Git** برنامج على حاسوبك. يعيش السجلّ كله في مجلد مخفي اسمه `.git` داخل مشروعك. إنشاء الـ commits والفروع والدمج وقراءة السجلّ كلها تحدث محليًا، وتعمل حتى وأنت في الطائرة.
- **GitHub** موقع وخدمة تستضيف مستودعات Git (repositories). يضيف حول Git ما يحتاجه الفريق: نسخة مشتركة يرفع إليها الجميع، و pull requests (طلبات الدمج) لمراجعة الكود، و issues، ولوحات المشاريع، و GitHub Actions للفحوص الآلية.

تستطيع استخدام Git دون GitHub (فرق كثيرة تستخدم GitLab أو Bitbucket)، لكن GitHub دون Git لا معنى له. يعلّمك هذا الكورس Git أولًا، ثم GitHub فوقه.

:::why لماذا يبدو Git صعبًا، وكيف يعالج هذا الكورس ذلك
يتعلّم معظم الناس Git كقائمة أوامر يحفظونها، فتبدو كل رسالة غير متوقَّعة كارثة. أوامر Git في الحقيقة حركات على رسم بياني صغير من الـ commits والأسماء الدالّة عليها. وحين تستطيع تخيّل هذا الرسم، يتوقّف الأمر عن كونه مقامرة ويصبح توقّعًا تستطيع التحقّق منه بـ `git log --graph`. توقّع الكثير من الرسوم التوضيحية.
:::

## ما الذي ستبنيه

ستعمل على مشروع واحد طوال الكورس: موقعك الشخصي، وهو repository (مستودع) اسمه `portfolio` فيه `index.html` و `styles.css` وصفحة للمشاريع وسكربت صغير `npm test` يفحص الـ HTML. في القسم الأول تحوّل المجلد إلى repository وتتعلّم قراءة سجلّه. في القسم الثاني تنشئ الفروع وتدمج وتنفّذ rebase وتصلح تعارضًا حقيقيًا. في القسم الثالث تضعه على GitHub وتعمل عبر الـ pull requests. وفي القسم الرابع تتعلّم التراجع عن الأخطاء بأمان، وتنتهي بفرع `main` محميّ تفحص فيه GitHub Actions كل pull request قبل أن يُسمح بدمجه.

في الدرس التالي تثبّت Git، وتعرّفه بنفسك، وتنشئ أول commit لك.
