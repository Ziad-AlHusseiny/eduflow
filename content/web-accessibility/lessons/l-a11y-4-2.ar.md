تقرأ مها Ticketly بتكبير 400% على حاسوب محمول بشاشة 13 بوصة. عند هذا التكبير، يصبح عرض نافذة متصفّحها فعليًا 320 بكسل CSS. بطاقات المهرجان، المصفوفة في ثلاثة أعمدة ثابتة بعرض 320px، تجبرها على التمرير أفقيًا مع كل سطر نص، وهذا يعني عند ذلك التكبير أنها تفقد موضعها باستمرار. وفي الوقت نفسه يمرّر الشريط المتحرّك في الصفحة الرئيسية أسماء الفنانين إلى ما لا نهاية، فيصاب زميلها توم، الذي يعاني اضطرابًا دهليزيًا (vestibular disorder) يؤثّر في التوازن، بصداع خلال دقيقة.

يتناول هذا الدرس ما يحدث حين يغيّر الناس حجم صفحتك، وحين تتحرّك صفحتك من تلقاء نفسها.

## التكبير وإعادة التدفّق

ثلاثة معايير تعمل معًا:

- **1.4.4 Resize Text ‏(AA):** يمكن تكبير النص إلى 200% دون فقدان محتوى أو وظيفة.
- **1.4.10 Reflow ‏(AA):** عند عرض **320 بكسل CSS**، يتّسع المحتوى دون تمرير أفقي. (نافذة بعرض 1280px عند تكبير 400% عرضها 320 بكسل CSS.) جداول البيانات والخرائط والمخطّطات مستثناة، لأنها تحتاج إلى بُعدين.
- **1.4.12 Text Spacing ‏(AA):** لا ينكسر شيء حين يفرض المستخدمون ارتفاع سطر قدره 1.5، والمسافة بين الفقرات إلى 2em، والمسافة بين الحروف إلى 0.12em، والمسافة بين الكلمات إلى 0.16em، كما يفعل كثير من ذوي عُسر القراءة عبر إضافة للمتصفّح.

إن كنت تبني بأسلوب متجاوب، فقد قطعت معظم الطريق. والمتّهمان المعتادان هما العروض الثابتة والارتفاعات الثابتة. شبكة البطاقات في Ticketly:

```css title=before.css
.cards {
  display: grid;
  grid-template-columns: repeat(3, 320px);
  gap: 16px;
}
.card h3 {
  height: 24px;      /* clips the title when text spacing grows */
  font-size: 18px;   /* doesn't follow the user's default font size */
}
```

```css title=after.css
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 16rem), 1fr));
  gap: 1rem;
}
.card h3 {
  font-size: 1.125rem;
}
```

الجزء `min(100%, 16rem)` مهم: في viewport عرضه 320px قد يظلّ عمود بعرض 16rem ‏(256px يُضاف إليها الحشو) يفيض، و`min()` تسمح للعمود بالانكماش إلى عرض الحاوية. وضبط النص بوحدة `rem` يعني أنه يكبر حين يضبط المستخدم حجم خط افتراضيًا أكبر في متصفّحه، وهي حالة لا يغطّيها التكبير وحده.

:::mistake تعطيل التكبير باللمس
نُسخ `<meta name="viewport" content="…, maximum-scale=1, user-scalable=no">` إلى مواقع لا تُحصى لمنع «التكبير غير المقصود». لكنه يمنع التكبير المقصود أيضًا، وهو الطريقة التي يستخدم بها ضعاف البصر الهاتف. استخدم `width=device-width, initial-scale=1` ولا شيء غيرهما.
:::

لاختبار إعادة التدفّق، اضبط نافذة المتصفّح على عرض 1280px وكبّر إلى 400%، أو استخدم الوضع المتجاوب في أدوات المطوّر بعرض 320px. مرّر عموديًا عبر الصفحة كلها. أي شريط تمرير أفقي، أو نص متداخل، أو زر مقطوع، خطأ.

## حجم الهدف من جديد

قابلت معيار 2.5.8 Target Size (Minimum) في درس [WCAG 2.2 ومبادئ POUR والقانون](lesson:l-a11y-1-3): أهداف المؤشّر لا تقلّ عن 24 × 24 بكسل CSS، أو تكون حول الأهداف الأصغر مسافة كافية. كان عدّاد الكمية في Ticketly يستخدم أزرار أيقونات بحجم 16px متلاصقة. والإصلاح بالحشو، لا بتكبير الأيقونات:

```css
.stepper button {
  min-inline-size: 2.75rem; /* 44px, comfortably above the 24px minimum */
  min-block-size: 2.75rem;
}
```

واطمح إلى ما هو أعلى من الحدّ الأدنى للأفعال الرئيسية على شاشات اللمس. إرشادات منصّتي Apple وGoogle تقترح نحو 44 إلى 48 بكسل، وسيشكرك المصابون بالرعاش.

## الحركة: أوقفها مؤقتًا، واحترم التفضيل

الحركة تسبّب مشكلتين مختلفتين. المحتوى الذي يتحرّك من تلقاء نفسه ينافس على الانتباه، وهذا عائق حقيقي لذوي اضطرابات الانتباه ولأي شخص يقرأ ببطء. والحركة الكبيرة، مثل الـ parallax أو الانتقالات المكبِّرة أو اللوحات المنزلقة، قد تثير الدوار والغثيان لدى المصابين باضطرابات دهليزية.

تعالج WCAG المشكلة الأولى بمعيار **2.2.2 Pause, Stop, Hide ‏(A)**: كل ما يبدأ تلقائيًا، ويتحرّك (أو يومض أو يتمرّر) أكثر من خمس ثوانٍ، ويظهر إلى جانب محتوى آخر، يحتاج إلى طريقة لإيقافه مؤقتًا أو إيقافه أو إخفائه. ويمنع معيار **2.3.1 Three Flashes or Below Threshold ‏(A)** المحتوى الذي يومض أكثر من ثلاث مرات في أي ثانية واحدة، إلا إن كانت الومضات صغيرة وخافتة بما يكفي لتبقى دون عتبات الوميض، لأن الوميض قد يثير نوبات صرع.

وللمشكلة الثانية، تتيح أنظمة التشغيل للمستخدمين طلب تقليل الحركة (في macOS: ‏Accessibility ثم Display ثم Reduce motion؛ وفي Windows: ‏Accessibility ثم Visual effects ثم إيقاف Animation effects)، ويستطيع CSS قراءة هذا الإعداد:

```css title=ticketly/motion.css
.marquee__track {
  animation: scroll-names 20s linear infinite;
}
.marquee--paused .marquee__track {
  animation-play-state: paused;
}

@media (prefers-reduced-motion: reduce) {
  .marquee__track {
    animation: none;
  }
  .card {
    transition: opacity 0.2s; /* a fade instead of a slide */
  }
}
```

```html
<button type="button" class="marquee-toggle" aria-pressed="false">Pause animation</button>
```

زر الإيقاف المؤقت ما زال ضروريًا: كثيرون ممّن تزعجهم الحركة لا يجدون إعداد النظام أبدًا، ومعيار 2.2.2 يشترط عنصر تحكّم في الصفحة. و«تقليل» الحركة لا يعني بالضرورة «انعدامها». التلاشي القصير أو تغيّر اللون نادرًا ما يسبّب مشكلة؛ الحركة الكبيرة عبر الشاشة هي التي تسبّبها.

الحركات التي تديرها JavaScript تحتاج إلى الفحص نفسه. تخبرك `window.matchMedia('(prefers-reduced-motion: reduce)').matches` بالتفضيل الحالي، ويمكنك الاستماع إلى حدث `change` الخاص بها لتستجيب إن غيّره المستخدم والصفحة مفتوحة.

:::tip الفيديو والوسائط ذاتية التشغيل
فيديوهات الخلفية تُحتسب محتوى متحرّكًا، وأي صوت يُشغَّل تلقائيًا لأكثر من ثلاث ثوانٍ يحتاج إلى عنصر تحكّم للإيقاف المؤقت أو لمستوى الصوت (1.4.2 Audio Control). وأبسط تصميم متوافق هو ألا تشغّل شيئًا تلقائيًا أصلًا.
:::

صار Ticketly متماسكًا حين يكبّره الناس، أو يباعدون نصّه، أو ينقرونه بيد مرتعشة، أو يطلبون منه أن يثبت في مكانه. ويعود الدرس التالي إلى شجرة إمكانية الوصول وينظر عن قرب في كيف يحصل كل عنصر تحكّم على الاسم الذي ينطقه قارئ الشاشة.
