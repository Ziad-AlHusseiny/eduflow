Automated tools told you what Ticketly is missing. A keyboard and a screen reader tell you what it is like to use. This is the part of testing that most teams skip, and it is the part that finds the problems people actually complain about. You don't need to become an expert screen reader user. You need about fifteen commands and a habit of listening carefully.

## The keyboard pass

Start every manual test without a mouse. Go from the address bar to the end of the page with Tab, then back with Shift+Tab, and at each stop ask:

1. **Can I reach it?** Every control a mouse can use must be reachable.
2. **Can I see it?** Focus is clearly visible and not hidden behind sticky bars.
3. **Is the order logical?** Focus follows the reading order of the page.
4. **Does it work?** Enter follows links and activates buttons; Space activates buttons and toggles checkboxes; arrow keys work inside radios, tabs and menus.
5. **Can I get out?** Escape closes dialogs and menus, focus returns to the opener, and nothing traps focus.

On Ticketly, this pass alone found the positive tabindex, the invisible focus, the div button and the modal that left focus behind, before anyone opened a screen reader.

## Which screen readers to test

In WebAIM's 2026 survey, the most common primary desktop screen readers were **JAWS** (55.0%) and **NVDA** (32.9%), both on Windows, followed by **VoiceOver** on macOS (6.5%). On mobile, 72.2% of respondents use **VoiceOver** on iOS, well ahead of **TalkBack** on Android (29.5%). A practical test matrix:

- **NVDA with Chrome or Firefox** on Windows. NVDA is free and open source, and behaves closely enough to JAWS to catch most problems.
- **VoiceOver with Safari** on macOS, built in.
- **VoiceOver on iOS** for anything people use on phones, which at a festival is almost everything.

## NVDA essentials

NVDA has two modes. In **browse mode**, NVDA reads the page with a virtual cursor and single letters jump between elements. In **focus mode**, keys go to the control, so you can type in a field. NVDA switches automatically when you enter a field, and NVDA+Space switches by hand. The **NVDA key** is Insert by default; you can also enable Caps Lock as the NVDA key, which is handy on laptops.

| Action | NVDA keys |
|---|---|
| Start NVDA / stop speech | Ctrl+Alt+N / Ctrl |
| Read from here | NVDA+Down Arrow |
| Next line or item | Down Arrow |
| Next heading / heading level 2 | H / 2 |
| Next landmark | D |
| Next form field / button / link | F / B / K |
| Next table, then move through cells | T, then Ctrl+Alt+Arrows |
| List of headings, links, landmarks | NVDA+F7 |

Add Shift to any single-letter command to go backwards.

## VoiceOver essentials (macOS)

Turn VoiceOver on and off with **Cmd+F5**. The **VO keys** are Control+Option. Before you start, open Safari's settings and enable **"Press Tab to highlight each item on a webpage"**; otherwise Tab skips links in Safari and you will report false bugs.

| Action | VoiceOver keys |
|---|---|
| Next / previous item | VO+Right / VO+Left |
| Activate | VO+Space |
| Read from here / stop speech | VO+A / Control |
| Next heading | VO+Cmd+H |
| Rotor (headings, links, landmarks, form controls) | VO+U, then Left/Right to switch lists |

On iOS, swipe right and left to move between items, double-tap to activate, and rotate two fingers on the screen to open the rotor.

:::mistake Testing only by reading top to bottom
New testers press "read all" and listen to the whole page. Real users almost never do that. Test the way they navigate: list the headings, jump by landmark, tab through the form, open the rotor's links list. That is where missing headings, duplicate "Book now" names and unlabelled landmarks become obvious.
:::

## What correct sounds like

Every interactive element should be announced with a **name**, a **role** and, where relevant, a **state** or value. Listen for the missing piece:

| You hear | Verdict |
|---|---|
| "Book now Friday pass, button" | Name and role: good |
| "Save to wishlist, toggle button, not pressed" | Name, role, state: good |
| "edit text, blank" | No name: the field has no label |
| "Pay now" (and Tab skips it) | No role, not focusable: a clickable div |
| "graphic, IMG underscore 2041 dot jpeg" | Missing alt attribute |
| "How do refunds work?, button" on a disclosure | No state: aria-expanded is missing |

Also listen for what doesn't happen: no announcement after adding a ticket, nothing said when a dialog opens, an error that appears silently.

## Writing it up

A finding a developer can fix in one go has six parts:

```text title=findings/ticketly-042.txt
Title:    Quantity stepper buttons have no accessible name
Where:    /events/friday, Friday pass card
Steps:    NVDA + Chrome. Tab to the "−" button after "Quantity".
Actual:   NVDA says "button". Same for "+".
Expected: "Fewer Friday passes, button" and "More Friday passes, button".
WCAG:     4.1.2 Name, Role, Value (A). Severity: high (blocks purchase).
```

:::why Why this matters
Testing with assistive technology yourself is not the same as testing with disabled people. Samir uses NVDA at a speed and with habits you won't reproduce in an afternoon. Your own testing catches the obvious barriers cheaply; paid usability sessions with disabled participants find the rest, and they are worth budgeting for at least once a year.
:::
